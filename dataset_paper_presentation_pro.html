Introduction

The real problem is not model design. It is missing data coverage.

Autonomous robots require perception systems that remain dependable in dynamic, unstructured, and safety-critical conditions, yet the training and validation data available for such scenarios remains narrow and difficult to control [1–3].

Why real-world collection falls short
Rare failures such as fog, dust, low light, and transparent obstacles are costly, risky, and hard to reproduce systematically [4–6].
Why a synthetic pipeline matters
Simulation gives repeatability, parameter control, and synchronized ground truth, which are essential for benchmarking sensor fusion under edge conditions [14–20].
Research gap
Existing public datasets
Strong for general perception, weak for controllable weather and adverse-condition stress testing [7–13].
Needed by fusion research
Aligned RGB, LiDAR, exact geometry, scene labels, and sensor reliability in a single sample.
Contribution

Four concrete takeaways, not four copied paragraphs

C1
Event-driven synchronized logging
The pipeline prevents race conditions by enforcing a causal sequence: spawn, stabilize, compute ground truth, then serialize.
C2
Controlled adverse conditions
Dust, fog, low light, and transparent materials are injected deliberately to create interpretable failure cases.
C3
Reliability-aware annotations
Each sample includes scene condition, geometry, and sensor-confidence cues that can supervise adaptive fusion.
C4
ROS 2 native extensibility
The architecture is modular enough to swap sensors, worlds, or annotation logic without rewriting the whole stack.

Pipeline

Three nodes, one deterministic data path

Scene Spawner
Chooses an object class, range band, pose, and environment condition; then issues the sampling trigger.
Ground Truth Listener
Reads model state and computes obstacle distance, angle, and semantic labels before data can be saved.
Data Logger
Serializes one synchronized triplet: image, LiDAR array, and JSON metadata.
Pipeline steps

What happens in one sample cycle

1
Spawn
Instantiate one of 22 obstacles within the configured distance band.
2
Settle
Wait 10 seconds so Gazebo physics stabilizes before capture.
3
Compute GT
Use model states to derive distance, angle, and scene labels.
4
Sync sensors
Camera and scan topics remain locked to the Gazebo clock at 10 Hz.
5
Serialize
Write exactly one JPEG, one LiDAR array, and one JSON file.
Environment design

Failure modes are engineered on purpose

Dust
Introduces strong visual clutter and perturbations in ranging, useful for robustness tests.
Fog / low light
Stress-tests sensing when visibility collapses or attenuation increases.
Transparent obstacles
Creates a high-value contradiction: the camera sees an object edge while LiDAR may report free space.

Use cases

How researchers can actually use this dataset

Camera-only regression baseline
Use the image tensor to predict distance with ResNet-34, Smooth L1 loss, AdamW, and cosine annealing over 100 epochs.
LIDAR-only baseline
Train a compact MLP directly on the 1 × 180 dense LiDAR vector without voxelization overhead.
Reliability-aware fusion
Use scene labels and sensor reliability tags to modulate attention weights when one modality degrades.
Ablation studies
Hold object pose constant and vary only weather or material properties to isolate failure mechanisms.
Future work

Natural next step: from one robot to many

Decentralized swarms
Extend the logger from a single centralized agent to distributed robots communicating through ROS 2 DDS.
Relative ground truth
Replace omniscient global labels with per-agent projections for collaborative perception and C-SLAM.
Asynchronous capture logic
Avoid burst traffic by letting each agent log only when local entropy or motion thresholds justify capture.
Big-picture value: the same dataset-generation logic can evolve into a testbed for collaborative robotics and V2X-style perception research.
Conclusion

The paper’s message in one slide

The contribution
A reproducible ROS 2 + Gazebo pipeline for synchronized RGB, LiDAR, and ground-truth dataset generation.
The differentiator
Reliability-aware metadata makes the dataset directly useful for context-aware and Bayesian fusion research.
The impact
Researchers can benchmark perception methods against repeatable, hard edge cases without hazardous real-world collection.
